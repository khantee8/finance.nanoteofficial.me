# NaNote Finance v0.3 — Auth0 Authentication Design

**Date:** 2026-05-14  
**Status:** Approved  
**Scope:** Access gate via Auth0 — real login, role-based routing, admin link hidden in sidebar footer. Demo data unchanged.

---

## Goal

Replace the fake `setTimeout` login with real Auth0 authentication. Only approved users can access the app. The demo screens, mock data, and UI are untouched — auth wraps the outside.

---

## What is NOT in scope

- Real portfolio data or database storage (still `lib/data.ts`)
- Multi-tenancy or firm management
- Email notifications for pending users
- Role self-service — admin assigns roles manually in Auth0 dashboard

---

## Architecture

```
Browser request
  └── middleware.ts (Next.js Edge)
        ├── /login, /api/auth/* → pass through (public)
        └── everything else → require Auth0 session cookie
              ├── no session → redirect to /login
              └── session exists → app/page.tsx (server component)
                    ├── role = pending / none → ScreenPending
                    ├── role = advisor → Shell (advisor view)
                    ├── role = client  → Shell (client view)
                    └── role = admin   → Shell (advisor view + admin footer link)
```

## Auth0 Tenant Configuration

### Application settings

| Setting | Value |
|---|---|
| Type | Regular Web App |
| Allowed Callback URLs | `https://finance.nanoteofficial.me/api/auth/callback`, `http://localhost:3001/api/auth/callback` |
| Allowed Logout URLs | `https://finance.nanoteofficial.me`, `http://localhost:3001` |
| Allowed Web Origins | `https://finance.nanoteofficial.me`, `http://localhost:3001` |

### Social connections

| Provider | Connection name |
|---|---|
| Google | `google-oauth2` |
| Instagram | `instagram` (via Facebook developer app) |
| Email/Password | `Username-Password-Authentication` |

### Post-Login Action

Paste into Auth0 → Actions → Flows → Login:

```js
exports.onExecutePostLogin = async (event, api) => {
  const role = event.user.app_metadata?.role ?? "pending";
  api.idToken.setCustomClaim("https://finance.nanoteofficial.me/role", role);
  api.accessToken.setCustomClaim("https://finance.nanoteofficial.me/role", role);
};
```

### Approving a new user

1. User signs up → appears in Auth0 dashboard → Users
2. Open their profile → `app_metadata` → set `{ "role": "advisor" }` (or `"client"`)
3. User logs in again → gets full access
4. To revoke access: set `role` to `"pending"` or delete the user

## Environment Variables

Add to Vercel (Settings → Environment Variables) and `.env.local`:

```bash
AUTH0_SECRET=             # openssl rand -hex 32
AUTH0_BASE_URL=https://finance.nanoteofficial.me
AUTH0_ISSUER_BASE_URL=https://<tenant>.auth0.com
AUTH0_CLIENT_ID=          # from Auth0 Application settings
AUTH0_CLIENT_SECRET=      # from Auth0 Application settings
```

For local dev, `AUTH0_BASE_URL=http://localhost:3001`.

## New Files

### `middleware.ts` (project root)

Protects all routes at the Next.js edge. Public paths: `/login` and `/api/auth/*`.

```
withMiddlewareAuthRequired()  →  @auth0/nextjs-auth0/edge
Matcher: excludes /login and /api/auth/*
```

### `app/api/auth/[auth0]/route.ts`

Auth0 SDK catch-all handler. Handles `/api/auth/login`, `/api/auth/callback`, `/api/auth/logout`.

```
handleAuth()  →  @auth0/nextjs-auth0
```

### `app/login/page.tsx`

Public page that renders `<ScreenLogin />`. Lives outside middleware protection. Redirects to `/` if user is already authenticated.

### `lib/auth.ts`

Thin helper — reads the role custom claim from the Auth0 session:

```ts
export async function getRole(): Promise<"advisor" | "client" | "admin" | "pending">
```

Used by `app/page.tsx` (server-side) to decide which view to render.

### `components/screens/ScreenPending.tsx`

Shown when `role === "pending"` or role is absent. Centred card:

- Message: "Your account is under review. You'll receive access once an admin approves your role."
- Logout button → `/api/auth/logout`
- NaNote branding (same left panel as login)

## Modified Files

### `app/page.tsx`

Convert from client component to **server component**. Calls `getRole()` from `lib/auth.ts`. No more `useState(loggedIn)`.

```ts
// Role → component mapping
pending → <ScreenPending />
advisor → <Shell initialView="advisor"> (with all advisor routes)
client  → <Shell initialView="client">  (with all client routes)
admin   → <Shell initialView="advisor"> (admin link visible in Shell footer)
```

Note: admin users enter via the advisor view by default. The admin console is accessed via the sidebar footer link.

### `components/Shell.tsx`

Two changes only:

1. **Remove** the `Advisor | Client | Admin` view toggle from the topbar — users are locked to their assigned role. The `view` state is initialised from `initialView` prop and never changes.
2. **Add** a small admin link in `sidebar-foot`, rendered only when `initialView === "admin"`:
   - Icon: `gear` (14px)
   - Tooltip: "Admin console"
   - `onClick`: sets `view` to `"admin"` and `route` to `"Admin"`
   - Visually: sits beside the existing gear icon, no label, subtle opacity

### `components/screens/ScreenLogin.tsx`

Only the button `onClick` handlers change — the card UI is untouched:

| Button | New handler |
|---|---|
| Continue with Google | `router.push("/api/auth/login?connection=google-oauth2")` |
| Facebook | `router.push("/api/auth/login?connection=facebook")` |
| Instagram | `router.push("/api/auth/login?connection=instagram")` |
| Sign in (email) | `router.push("/api/auth/login")` with email hint |
| Role tabs | Removed — role is determined by Auth0, not user selection |

The role tabs (`Advisor / Client / Admin`) are removed from the login card. The card becomes a clean login-only UI with no role selection.

### `next.config.ts`

Add Auth0 tenant domain to CSP:

```ts
"connect-src 'self' https://api.anthropic.com https://<tenant>.auth0.com",
"frame-src 'self' https://<tenant>.auth0.com",
```

### `package.json`

Add one dependency: `@auth0/nextjs-auth0`

## User Flows

### New user signs up

```
Login page → clicks Google → Auth0 OAuth → callback → session set
→ app/page.tsx reads role = "pending" → ScreenPending shown
→ Admin opens Auth0 dashboard → sets app_metadata.role = "advisor"
→ User logs out and back in → advisor workspace
```

### Returning approved user

```
Visits finance.nanoteofficial.me → middleware checks session
→ session valid → app/page.tsx reads role → correct view shown immediately
```

### Admin accesses console

```
Logs in (role = "admin") → lands on advisor workspace
→ sidebar footer: small gear icon → clicks → view switches to Admin console
→ 5-tab admin dashboard (Overview / Users / Compliance / Audit / Billing)
```

### Session expiry

```
Session expires → next request → middleware redirects to /login
→ user logs in again → back to their view
```

## Security notes

- Auth0 session cookie is `HttpOnly`, `Secure`, `SameSite=Lax` — managed by the SDK
- `AUTH0_SECRET` must be a random 32-byte string — never commit to git
- Role is read from `app_metadata` (not `user_metadata`) — users cannot self-modify it
- Instagram connection requires a Facebook Developer App with Instagram Basic Display API enabled
- CSP must include Auth0 tenant domain before deploying — without it, the OAuth redirect silently fails
